01 Compute CPU policy · RAM · storage type · expected I/O
02 Network Transfer · port speed · IP terms · region · route
03 Platform OS images · panel options · license cost
04 Operations Backups · firewall · DDoS · monitoring · support scope
05 Billing & upgrade path Billing cadence · renewal terms · add-ons · upgrade limits · extra charges
Shortlist Keep only providers that match the workload and operating model
Performance fit Location fit Management fit Cost fit

01 FASTPANEL Domains · SSL · PHP versions · databases · multiple sites
Simpler workflow · panel uses RAM
02 Ubuntu + SSH Nginx or Apache · runtime · database · shell administration
More control · more work stays with you
03 Windows when required Use this path for genuine IIS or ASP.NET requirements

Self-managed VPS You own the operating system Patching · security · backups · monitoring · incident response

{{ else if eq .id "migration-preflight" }}
Migration preflight Map the stack before you move it Build the migration plan from the current website, dependencies and rollback requirements before production traffic changes.
01 Inventory CMS/framework · runtime versions · DB · cron · storage · DNS · SSL · email
02 Find blockers Extensions · runtime mismatch · DB assumptions · local file dependencies
03 Build test copy Prepare the new VPS without touching production traffic
04 Sync & validate Files · database · integrations · forms · jobs · SSL · mail behavior
05 DNS cutover Move production traffic only after the new environment passes checks
Rollback path Keep the previous working environment available Know exactly how to reverse the move if validation fails after cutover.
Email decision Move mail only when it should move Keeping email on a managed mail service can reduce deliverability and administration risk.
Purchase decision Choose the VPS configuration after the migration inventory shows the real requirements.

{{ else if eq .id "safe-growth" }}
Reversible operations Change the server without betting production Use copies, monitoring and recovery points so upgrades and scaling decisions remain reversible.
01 Clone Create a copy before risky changes
02 Test Validate upgrades and architecture changes away from production
03 Monitor Watch CPU, memory, storage growth and request queues
04 Scale Add resources only when pressure is sustained
CPU saturation Memory pressure Storage growth Request queues
Snapshot Fast rollback point Useful for quick reversal, but not the only recovery copy.

Portable copy Keep recovery outside the running VPS Maintain an independent copy under your own control.
Operating rule Measure first, change second, keep a way back.
