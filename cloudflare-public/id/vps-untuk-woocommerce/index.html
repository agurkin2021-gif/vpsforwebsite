Persyaratan WooCommerce bukan patokan spesifikasi VPS produksi

Rekomendasi server WooCommerce saat ini untuk WooCommerce 10.8+ memerlukan:

  • WordPress 6.9+;
  • PHP 8.3+;
  • MySQL 8.0+ atau MariaDB 10.6+;
  • HTTPS;
  • batas memori WordPress 256 MB+;
  • Apache atau Nginx sebagai pilihan server web yang direkomendasikan.

Persyaratan tersebut menjawab pertanyaan “apakah lingkungan memenuhi dasar perangkat lunak WooCommerce?”

Persyaratan itu belum menjelaskan:

  • berapa banyak worker PHP yang dibutuhkan;
  • berapa total RAM VPS yang diperlukan;
  • apakah data aktif database dapat ditampung di memori;
  • apakah permintaan checkout mengantre saat beban meningkat;
  • apakah tindakan yang dijadwalkan terlambat;
  • apakah backup atau impor berebut sumber daya dengan aktivitas pelanggan;
  • apakah integrasi pembayaran/webhook menunda permintaan.

Batas memori 256 MB pada WordPress/PHP tidak berarti VPS cukup memiliki RAM 256 MB. Total RAM server juga harus menampung Linux, server web, database, worker PHP, cache, tugas terjadwal, panel, email, dan cadangan kapasitas.

Cek Kebutuhan VPS untuk WooCommerce

Gunakan alat ini untuk memilih konfigurasi awal, lalu validasi dengan pengujian beban toko Anda.

Pilih beban kerja yang paling sesuai dengan toko Anda.

Kapan WooCommerce membutuhkan VPS?

Toko WooCommerce dapat membutuhkan VPS ketika:

  • shared hosting berulang kali mencapai batas CPU, memori, proses, atau I/O saat melayani beban yang diperlukan;
  • permintaan checkout/akun mengantre saat melayani beban nyata;
  • set data aktif DB atau beban tulis memerlukan kontrol lebih besar;
  • ekstensi memerlukan layanan yang tidak diizinkan oleh host saat ini;
  • Redis/Memcached atau konfigurasi server khusus diperlukan;
  • Action Scheduler/tugas latar belakang memerlukan eksekusi yang lebih andal;
  • impor produk, feed, atau sinkronisasi inventaris bertabrakan dengan lalu lintas pelanggan;
  • pengaturan khusus PHP/runtime/server web diperlukan;
  • lingkungan staging atau kontrol operasional khusus toko diperlukan.

Jika toko kecil, stabil, dan mendapat dukungan yang baik pada hosting WooCommerce/WordPress managed, VPS tidak otomatis menjadi pilihan yang lebih baik.

Kapan hosting WooCommerce managed lebih tepat

VPS yang dikelola sendiri kurang cocok jika:

  • belum ada penanggung jawab pembaruan OS/keamanan;
  • tidak ada yang memantau ketersediaan checkout atau peringatan server;
  • cadangan ada tetapi pemulihan belum diuji;
  • gangguan pembayaran atau pemesanan berdampak besar pada bisnis;
  • tim menginginkan bantuan WordPress/WooCommerce daripada administrasi Linux;
  • platform terkelola yang ada sudah menyelesaikan masalah kinerja dan penskalaan secara memadai.

VPS memberi kontrol lebih besar, tetapi juga menambah jenis kegagalan yang menjadi tanggung jawab Anda.

Baca VPS Managed vs Unmanaged sebelum menempatkan toko yang penting bagi pendapatan pada server yang dikelola sendiri.

Checkout dan akun pelanggan tetap dinamis

Panduan cache WooCommerce menyatakan Keranjang, Akun Saya, dan Checkout harus dikecualikan dari cache halaman penuh karena menampilkan data khusus setiap pelanggan.

Proses yang penting bagi penjualan ini tetap dapat menjalankan:

  • PHP;
  • logika sesi/keranjang;
  • logika pengiriman/pajak;
  • kode integrasi pembayaran;
  • pembacaan/penulisan database;
  • pembuatan pesanan;
  • pembaruan stok;
  • hook dan ekstensi.

Oleh karena itu, toko dapat menyajikan halaman produk yang disimpan dalam cache dengan cepat sementara checkout masih mengantri.

Jangan mengukur WooCommerce hanya dari tingkat hit cache di katalog.

Worker PHP dan permintaan dinamis bersamaan

Jumlah worker PHP membatasi berapa banyak permintaan dinamis WooCommerce yang dapat diproses pada saat yang sama.

Perkiraan yang berguna adalah:

permintaan dinamis aktif ≈ permintaan tanpa cache per detik × durasi permintaan

Jika permintaan checkout/account/API rata-rata 0,8 detik pada puncaknya dan 5 permintaan dinamis per detik mencapai PHP, kira-kira empat worker dapat sibuk sekaligus sebelum tugas admin, webhook atau tugas latar belakang ditambahkan.

Setiap worker memakai memori. Menambah jumlahnya tanpa RAM yang cukup dapat membuat database kekurangan memori, meningkatkan penggunaan swap, atau memicu penghentian proses karena OOM.

Gunakan:

RAM WooCommerce = OS + server web + database + cache + worker PHP + tugas + panel/email + cadangan kapasitas

Ukur pemakaian memori rata-rata dan puncak per worker sebelum menentukan jumlahnya.

Konfigurasi cache WooCommerce yang tepat

WooCommerce memerlukan strategi cache berlapis.

Cache halaman penuh

Berguna untuk halaman katalog/konten yang dapat di-cache.

Jangan sembarangan menerapkan cache pada:

  • Keranjang;
  • checkout;
  • Akun Saya;
  • respons yang khusus untuk pelanggan atau sesi tertentu.

Panduan caching resmi WooCommerce secara eksplisit mengecualikan halaman tersebut.

OPcache

Menyimpan bytecode PHP yang dikompilasi dalam cache dan mengurangi tugas kompilasi PHP yang berulang.

Cache objek persisten

Redis atau Memcached dapat mengurangi tugas database/objek yang berulang ketika beban kerja diuntungkan.

Ini tidak menggantikan cache satu halaman penuh dan tidak secara otomatis memperbaiki kueri yang tidak efisien.

Peramban / CDN

Berguna untuk aset statis dan konten yang dapat dilayani dari server edge CDN.

CDN dapat mengurangi permintaan origin statis tetapi tidak menghapus tugas dinamis checkout/database.

Beban database dan HPOS

WooCommerce menciptakan perilaku baca/tulis database yang lebih berat daripada situs WordPress yang di-cache pada umumnya.

Tugas DB yang penting dapat mencakup:

  • pembuatan dan pembaruan pesanan;
  • data pelanggan/akun;
  • perubahan stok;
  • pencarian produk/katalog;
  • sesi;
  • metadata ekstensi;
  • laporan/analisis;
  • pencarian/pemfilteran;
  • tugas terjadwal.

WooCommerce High-Performance Order Storage (HPOS) menyimpan data pesanan dalam tabel khusus dan diaktifkan secara default untuk instalasi baru sejak WooCommerce 8.2.

HPOS merupakan perbaikan arsitektur yang penting, namun bukan pengganti:

  • ekstensi dan kode khusus yang kompatibel;
  • tinjauan kueri/indeks;
  • memori DB yang memadai;
  • latensi penyimpanan rendah;
  • pemantauan;
  • lingkungan staging/pengujian sebelum perubahan besar.

Untuk toko besar yang sudah berjalan, WooCommerce menyarankan pengujian migrasi HPOS dan alur penting sebelum mengalihkan lingkungan produksi.

Action Scheduler dan tugas latar belakang

WooCommerce menggunakan Action Scheduler untuk tugas latar belakang seperti:

  • pemberitahuan pesanan;
  • pemrosesan terkait pembayaran;
  • webhook;
  • langganan/perpanjangan;
  • tugas ekstensi;
  • impor/sinkronisasi.

Daftar tugas tersedia melalui menu WooCommerce > Status > Scheduled Actions (Tindakan Terjadwal).

Perhatikan:

  • tindakan yang gagal;
  • tugas yang melewati waktu eksekusinya;
  • penumpukan tugas tertunda yang terus berlangsung;
  • tugas yang memerlukan waktu lama;
  • antrean yang bertambah saat trafik pelanggan memuncak.

Action Scheduler bergantung pada penjadwalan WordPress secara default, sehingga cron sisi server dapat berguna jika diperlukan pengaturan waktu yang andal.

Toko dengan halaman cache yang cepat masih dapat mengalami masalah operasional jika antrean terjadwalnya gagal.

Pembayaran, webhook, email dan integrasi

VPS yang lebih besar tidak dapat memperbaiki setiap kegagalan checkout.

Dependensi eksternal dapat mencakup:

  • payment gateway;
  • API pajak;
  • API pengiriman;
  • sinkronisasi inventaris/ERP;
  • CRM;
  • email transaksional;
  • pemeriksaan penipuan;
  • webhook;
  • pencarian/layanan eksternal.

Ukur apakah latensi berasal dari VPS Anda atau dari layanan eksternal.

Pantau:

  • kegagalan callback pembayaran;
  • pengiriman webhook;
  • antrean email;
  • timeout API;
  • perilaku percobaan ulang dan jeda backoff;
  • kegagalan Action Scheduler.

Jangan membeli CPU untuk mengatasi kemacetan API pihak ketiga.

Katalog, pencarian dan pemfilteran

Beban katalog tidak ditentukan oleh jumlah produk saja.

Tekanan sebenarnya datang dari:

  • kueri pencarian/filter yang kompleks;
  • kueri atribut/taksonomi;
  • tabel pencarian produk;
  • jumlah variasi;
  • aturan harga/stok;
  • ekstensi yang menambahkan SQL atau panggilan eksternal;
  • hasil personalisasi tanpa cache.

Ukur titik akhir pencarian/filter secara terpisah dari penelusuran halaman produk normal.

Cache persisten dapat membantu mengurangi kueri berulang, tetapi desain database dan efisiensi kueri tetap perlu diperhatikan.

Menentukan kapasitas untuk puncak penjualan dan kampanye

Beban puncak WooCommerce sering kali menggabungkan beberapa hal sekaligus:

  • trafik dari newsletter atau iklan;
  • penjelajahan katalog;
  • penambahan produk ke keranjang;
  • checkout;
  • callback pembayaran;
  • email pesanan;
  • pembaruan stok;
  • admin/pemrosesan pesanan;
  • webhook;
  • tindakan terjadwal;
  • analitik/pencatatan log.

Tentukan spesifikasi untuk periode puncak yang mewakili beban nyata, bukan hari rata-rata.

Sebelum promosi besar:

  1. uji trafik checkout yang mewakili penggunaan nyata;
  2. periksa cadangan kapasitas worker PHP;
  3. periksa latensi dan koneksi database;
  4. periksa penumpukan tugas Action Scheduler;
  5. jeda atau jadwalkan ulang impor/cadangan/pemindaian;
  6. pastikan API pembayaran, pengiriman, dan pajak siap digunakan;
  7. pantau log dan metrik sumber daya selama acara.

Penyimpanan, backup, dan staging

Backup WooCommerce harus mencakup file situs sekaligus data transaksi.

Sertakan:

  • file WordPress/WooCommerce;
  • unggahan/media produk;
  • database/data pesanan;
  • konfigurasi/rahasia yang diperlukan untuk pemulihan;
  • plugin/tema/kode khusus;
  • pengaturan integrasi.

Pemulihan dengan mempertimbangkan transaksi

Jika toko menerima pesanan secara terus-menerus, frekuensi pencadangan menentukan potensi kehilangan data pesanan.

Pencadangan DB harian dapat berarti hingga satu hari transaksi terkini berada di luar titik pemulihan tersebut.

Pilih frekuensi pencadangan dari target titik pemulihan (RPO) yang dapat diterima bisnis, bukan sekadar jadwal yang paling mudah dijalankan.

Pembahasan mendalam arsitektur backup ada di Strategi Backup VPS.

Lingkungan staging

Uji perubahan pada PHP, WooCommerce, plugin, tema, HPOS, dan pembayaran di lingkungan staging sebelum produksi jika memungkinkan.

Namun salinan lingkungan staging juga menggunakan sumber daya disk dan terkadang sumber daya DB/RAM/cadangan, jadi sertakan sumber daya tersebut dalam perencanaan kapasitas.

Panel kontrol, FASTPANEL atau stack manual

WooCommerce dapat berjalan di VPS Linux yang dikelola secara manual atau melalui panel kontrol hosting.

Untuk pemilihan panel umum, lihat VPS dengan Panel Kontrol.

Untuk jalur khusus VDSina FASTPANEL, lihat Hosting VPS dengan FASTPANEL.

Untuk instalasi Linux secara manual, lihat Cara menghosting website di VPS.

Panel kontrol menyederhanakan tugas rutin; tanggung jawab keandalan checkout, pembaruan WooCommerce/plugin, penyetelan DB, backup, dan insiden tetap harus ditangani.

Migrasi toko aktif harus menjaga konsistensi data

Migrasi WooCommerce tidak hanya “menyalin file dan DB”.

Pesanan, stok, keranjang, pelanggan, dan tindakan terjadwal dapat berubah saat toko aktif.

Untuk migrasi:

  • siapkan dan uji server tujuan terlebih dahulu;
  • atur kapan penulisan data terakhir dilakukan;
  • jalankan sinkronisasi terakhir database dan unggahan;
  • hindari perbedaan data antara dua toko produksi yang sama-sama menerima penulisan;
  • verifikasi endpoint pembayaran dan webhook;
  • pertahankan email/DNS;
  • pertahankan rencana rollback.

Gunakan Migrasi website ke VPS untuk proses peralihan selengkapnya.

Kapan perlu upgrade VPS WooCommerce?

Skalakan atau rancang ulang ketika pengukuran menunjukkan:

  • antrean permintaan PHP yang terus berulang;
  • saturasi CPU berkelanjutan setelah optimasi cache/query/plugin;
  • tekanan RAM, penggunaan swap, atau kejadian OOM;
  • latensi database atau memori yang tidak cukup untuk data aktifnya;
  • penumpukan tugas atau kegagalan Action Scheduler akibat keterbatasan kapasitas;
  • kesalahan checkout atau pembayaran saat beban nyata memuncak;
  • pertumbuhan penyimpanan mengurangi cadangan kapasitas yang aman;
  • backup, impor, atau pemindaian berebut sumber daya dengan aktivitas pelanggan;
  • beberapa toko/layanan bersaing untuk satu VPS.

Jika checkout lambat sementara sumber daya server sehat, selidiki penyebab pembayaran/API/plugin/database sebelum membeli VPS yang lebih besar.

Pertanyaan Umum

Berapa RAM yang dibutuhkan WooCommerce di VPS?

Tidak ada angka yang berlaku untuk semua toko. Panduan penskalaan WooCommerce pernah menggunakan 2 GB sebagai konfigurasi dasar hosting yang dikelola sendiri. Untuk banyak toko bisnis, 4 GB menjadi titik awal yang lebih longgar karena worker PHP, database, cache, dan tugas latar belakang berjalan bersama.

Apakah RAM 2 GB cukup untuk WooCommerce?

Bisa, untuk toko yang sangat ringan dengan volume transaksi rendah dan terkontrol. Uji checkout bersamaan, latensi database, tugas terjadwal, dan pemakaian memori sebelum menggunakannya untuk produksi.

Apakah RAM 4 GB cukup untuk WooCommerce?

Untuk banyak toko bisnis kecil, 4 GB merupakan titik awal yang praktis. Trafik tinggi, katalog atau database besar, banyak integrasi, langganan, impor, dan lonjakan penjualan dapat memerlukan kapasitas tambahan.

Mengapa WooCommerce lebih berat dari WordPress biasa?

Keranjang, checkout, akun, pesanan, stok, dan banyak integrasi bersifat dinamis. Permintaan tersebut tetap menjalankan pemrosesan PHP dan database walaupun halaman katalog atau konten publik memakai cache.

Bisakah checkout WooCommerce di-cache?

Caching satu halaman penuh harus mengecualikan Keranjang, checkout, dan Akun Saya karena halaman tersebut berisi status khusus pelanggan. Gunakan lapisan cache lainnya untuk data/konten yang sesuai.

Apakah WooCommerce memerlukan Redis?

Tidak selalu. Redis atau Memcached dapat menyediakan cache objek persisten jika sesuai dengan beban toko. Kueri tetap harus efisien, dan halaman khusus pelanggan tetap harus dikecualikan dari cache halaman penuh.

Apa itu HPOS?

High-Performance Order Storage menyimpan pesanan WooCommerce dalam tabel khusus. Fitur ini aktif secara default pada instalasi baru sejak WooCommerce 8.2. Uji kompatibilitas ekstensi/kode khusus dan alur penting toko saat mengubah toko yang sudah berjalan.

Apa yang dimaksud dengan Tindakan Terjadwal WooCommerce?

Tindakan Terjadwal adalah tugas latar belakang dalam antrean Action Scheduler, seperti notifikasi pesanan, pemrosesan terkait pembayaran, webhook, dan tugas ekstensi. Tugas yang gagal atau melewati jadwal perlu diperiksa karena dapat mengganggu operasional toko.

Apakah VDSina menyertakan WooCommerce yang sudah diinstal sebelumnya?

Halaman Standard VDSina saat ini tidak menampilkan WooCommerce sebagai aplikasi siap instal tersendiri. Periksa pilihan yang tersedia saat memesan sebelum mengandalkan template tertentu.

Apakah VPS selalu lebih baik untuk WooCommerce dibandingkan hosting terkelola?

Tidak. VPS yang dikelola sendiri berguna jika Anda membutuhkan kontrol atau sumber daya dan mampu mengoperasikan server. Hosting WooCommerce/WordPress managed dapat lebih aman bila toko penting bagi bisnis dan belum ada penanggung jawab internal untuk administrasi server.
