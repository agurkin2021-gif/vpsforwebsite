VPS para WooCommerce

VPS para WooCommerce: dimensione CPU e RAM considerando os checkouts simultâneos, os processos PHP, as gravações no banco de dados, o Action Scheduler, as integrações e os picos de vendas. Depois, escolha a forma de gerenciamento adequada.

Um VPS para WooCommerce deve ser dimensionado para as partes da loja que não funcionam como um blog em cache: carrinho, checkout, conta, pedidos, estoque, callbacks de pagamento, ações agendadas e gravações no banco de dados. As visitas mensais ou a quantidade de produtos, por si só, não indicam quantos recursos de servidor a loja precisa.

Para a carga de trabalho mais ampla do WordPress, veja VPS para o WordPress. Para o caminho central de compra de servidores, consulte VPS para sites.

A própria orientação de escalabilidade do WooCommerce usou 1 vCPU + pelo menos 2 GB de RAM como uma configuração auto-hospedada fundamental com OPcache, CDN e suporte a cache persistente. Isso é um piso inicial, não uma promessa de que uma loja de produção permanecerá confortável lá.

Preços atuais dos planos VDSina Standard conferidos novamente em 13 de outubro de 2026:

  • 1 vCPU / 1 GB / 10 GB / 1 TB de transferência mensal — US$ 0,07/dia;
  • 1 vCPU / 2 GB / 40 GB / 32 TB — US$ 0,50/dia;
  • 2 vCPU / 4 GB / 80 GB / 32 TB — US$ 0,67/dia;
  • 4 vCPU / 8 GB / 160 GB / 32 TB — US$ 1,34/dia.

Para muitas lojas de negócios reais, 4 GB é o nível inicial mais prático porque o VPS deve carregar o sistema operacional, banco de dados, processos PHP, cache, tarefas em segundo plano e margem de capacidade operacional ao mesmo tempo.

Dimensionamento de VPS para sites

Os requisitos do WooCommerce não definem o dimensionamento de um VPS em produção

As recomendações atuais do servidor do WooCommerce para o WooCommerce 10.8+ exigem:

  • WordPress 6.9+;
  • PHP 8.3+;
  • MySQL 8.0+ ou MariaDB 10.6+;
  • HTTPS;
  • Limite de memória do WordPress de 256 MB ou mais
  • Apache ou Nginx como opções recomendadas de servidor web.

Esses valores respondem "o ambiente atende à linha de base do software do WooCommerce?"

Eles não respondem:

  • quantos processos PHP você precisa;
  • Quanta RAM VPS total é necessária;
  • se o conjunto de dados DB mantido na memória se encaixa na memória;
  • se as requisições de checkout formam filas sob carga.
  • Se as ações agendadas estão atrasadas;
  • se backups/importações colidem com clientes;
  • se as integrações de pagamento/webhook estão atrasando solicitações.

Um limite de memória 256 MB WordPress/PHP não é 256 MB de VPS RAM. A RAM total do servidor também deve cobrir Linux, servidor web, DB, processos PHP, cache, tarefas, painel/mail e margem de capacidade.

Quando o WooCommerce realmente precisa de VPS

Uma loja WooCommerce pode justificar VPS quando:

  • hospedagem compartilhada atinge repetidamente os limites legítimos de CPU/memória/processo/I/O;
  • requisições de checkout/conta formam filas sob carga real;
  • o conjunto de dados DB mantido na memória ou carga de gravação precisa de mais controle;
  • extensões precisam de serviços que o host atual não permite;
  • Redis/Memcached ou configuração de servidor personalizada é necessária;
  • o Action Scheduler e as tarefas em segundo plano precisam de execução confiável;
  • importações de produtos, feeds ou sincronização de inventário colidem com o tráfego do cliente;
  • são necessárias configurações personalizadas do ambiente PHP/execução/servidor web;
  • ambiente de teste ou controle operacional específico da loja é necessário.

Se a loja é pequena, estável e bem suportada na hospedagem gerenciada do WooCommerce/WordPress, o VPS não é automaticamente a melhor escolha.

Quando a hospedagem gerenciada para WooCommerce pode ser melhor

Um VPS auto-gerenciado é uma má escolha quando:

  • ninguém é responsável pelas atualizações e pela segurança do sistema operacional;
  • ninguém monitora a disponibilidade de checkout ou alertas do servidor;
  • backups existem, mas a restauração não é testada;
  • o tempo de inatividade do pagamento/ordem é crítico para os negócios;
  • a equipe quer ajuda do WordPress/WooCommerce em vez da administração do Linux;
  • a plataforma gerenciada existente já resolve o desempenho e o escalonamento adequadamente.

O VPS oferece mais controle, mas também traz mais tipos de falha para você administrar.

Veja VPS gerenciado ou não gerenciado antes de colocar uma loja essencial para a receita em um servidor administrado por você.

Checkout e tráfego da conta permanecem dinâmicos

A própria documentação de cache do WooCommerce orienta excluir Carrinho, Minha conta e Checkout do cache de página inteira, pois essas páginas contêm dados específicos de cada cliente.

As requisições mais importantes ainda podem executar:

  • PHP;
  • lógica de sessão/carrinho;
  • lógica de envio/impostos;
  • código de integração de pagamento;
  • leituras/escritas de banco de dados;
  • criação de pedidos;
  • atualizações de estoque;
  • hooks e extensões;

Uma loja pode, portanto, servir uma página de produto em cache rapidamente enquanto o checkout ainda está na fila.

Não dimensione o WooCommerce a partir da taxa de cache do catálogo sozinho.

Processos PHP e simultaneidade dinâmica

Para solicitações dinâmicas do WooCommerce, os processos PHP determinam quantas solicitações podem ser executadas simultaneamente.

Uma aproximação útil é:

requisições dinâmicas ativas ≈ requisições sem cache por segundo × duração da requisição

Se o checkout/conta/API solicitar média de 0,8 segundos no pico e 5 solicitações dinâmicas por segundo alcançarem o PHP, cerca de quatro processos podem estar ocupados ao mesmo tempo antes do trabalho de administração, webhooks ou tarefas em segundo plano serem adicionadas.

Aumentar o número de processos PHP sem RAM suficiente pode deixar o banco de dados sem recursos, causar uso de swap ou provocar encerramentos por falta de memória.

Use:

RAM para WooCommerce = SO + servidor web + banco de dados + cache + processos PHP + tarefas + painel/e-mail + margem de capacidade

Em seguida, verifique a memória média/pico do processo em vez de copiar uma contagem de processos genéricos.

Cache WooCommerce corretamente

WooCommerce precisa de uma estratégia de cache em camadas.

Cache de página inteira

Útil para páginas de catálogo/conteúdo que podem usar cache.

Não armazene indiscriminadamente em cache:

  • Carrinho;
  • Checkout;
  • Minha conta;
  • respostas específicas do cliente/sessão.

A orientação oficial de cache do WooCommerce exclui explicitamente essas páginas.

OPcache

Armazena em cache o bytecode PHP compilado e reduz a recompilação.

Cache de objetos persistente

Redis ou Memcached podem reduzir o trabalho repetido de banco de dados/objeto quando a carga de trabalho se beneficia.

Ele não substitui o cache de página inteira e não corrige automaticamente consultas ineficientes.

Navegador / CDN

Útil para arquivos estáticos e conteúdo que pode ser entregue pela CDN.

Uma CDN pode reduzir solicitações de origem estática, mas não remove o trabalho dinâmico de checkout/banco de dados.

Demanda de banco de dados e HPOS

O WooCommerce cria um comportamento de leitura/gravação de banco de dados mais pesado do que um site WordPress em cache típico.

O trabalho importante do banco de dados pode incluir:

  • criação e atualização de pedidos;
  • dados de cliente/conta;
  • Mudanças de estoque;
  • pesquisa de produtos/catálogos;
  • sessões;
  • metadados de extensão;
  • relatórios/análises;
  • pesquisa/filtragem;
  • tarefas agendadas.

O WooCommerce High-Performance Order Storage (HPOS) armazena dados de pedidos em tabelas dedicadas e é habilitado por padrão para novas instalações desde o WooCommerce 8.2.

HPOS é uma importante melhoria arquitetônica, mas não é um substituto para:

  • extensões compatíveis/código personalizado;
  • consulta/revisão de índice;
  • memória DB adequada;
  • baixa latência de armazenamento;
  • monitoramento;
  • testes em homologação antes de grandes mudanças.

Para lojas grandes já existentes, o WooCommerce recomenda testar a migração para HPOS e os fluxos críticos antes da virada em produção.

Action Scheduler e trabalho em segundo plano

O WooCommerce usa Action Scheduler para tarefas em segundo plano, como:

  • Notificações de pedidos;
  • processamento relacionado ao pagamento;
  • Webhooks;
  • assinaturas/renovações;
  • tarefas de extensão;
  • Importações/sincronização.

O WooCommerce mostra essas ações em WooCommerce > Status > Ações agendadas.

Cuidado com:

  • ações fracassadas;
  • ações atrasadas;
  • acúmulo persistente de ações pendentes;
  • tarefas de longa duração;
  • filas que crescem durante os picos de clientes.

O Action Scheduler depende do agendamento do WordPress por padrão, portanto, o cron do lado do servidor pode ser útil onde o tempo confiável é necessário.

Uma loja com páginas em cache rápido ainda pode ter problemas operacionais se a fila programada estiver falhando.

Pagamentos, webhooks, e-mail e integrações

Um VPS maior não pode consertar todas as falhas de checkout.

Dependências externas podem incluir:

  • gateways de pagamento;
  • APIs fiscais;
  • APIs de envio;
  • Inventário/sincronização ERP;
  • CRM;
  • e-mail transacional;
  • verificações de fraude;
  • Webhooks;
  • Pesquisa/serviços externos.

Meça se a latência se origina do seu VPS ou do serviço externo.

Monitore:

  • falhas de callback de pagamento;
  • entrega webhook;
  • filas de e-mail;
  • Tempo limite da API;
  • comportamento das novas tentativas e dos intervalos entre elas;
  • Falhas no Action Scheduler.

Não compre CPU para resolver um gargalo de API de terceiros.

Catálogo, pesquisa e filtragem

Catálogos grandes não criam carga apenas porque contêm muitos produtos.

A pressão real vem de:

  • consultas complexas de pesquisa/filtro;
  • consultas de atributo/taxonomia;
  • tabelas de pesquisa de produtos;
  • quantidade de variações;
  • regras de preços / estoque;
  • extensões que adicionam SQL ou chamadas externas;
  • Resultados personalizados sem cache.

Meça os endpoints de pesquisa/filtro separadamente da navegação normal na página do produto.

O cache persistente pode ajudar algumas consultas repetidas, mas o design do banco de dados/consulta ainda é importante.

Dimensione para picos de vendas e campanhas

WooCommerce pico de carga muitas vezes combina várias coisas ao mesmo tempo:

  • boletim informativo/tráfego de anúncios;
  • Catálogo de navegação;
  • Adicionar ao carrinho;
  • checkout;
  • callbacks de pagamento;
  • e-mails de pedidos;
  • atualizações de estoque;
  • administração e processamento de pedidos.
  • Webhooks;
  • ações agendadas;
  • analytics/logging.

Dimensione pela janela de pico representativa, não pelo dia médio.

Antes de uma grande promoção:

  1. teste tráfego representativo de checkout;
  2. verificar a margem de capacidade do processo PHP;
  3. verificar latência e conexões de banco de dados;
  4. verificar o backlog do Action Scheduler;
  5. pausar ou reagendar importações/backups/scans;
  6. confirmar APIs de pagamento/envio/imposto externo;
  7. observe registros e métricas de recursos durante o evento.

Armazenamento, backups e ambiente de teste

Um backup do WooCommerce deve proteger arquivos e dados transacionais.

Inclua:

  • Arquivos do WordPress/WooCommerce;
  • uploads/mídia de produto;
  • banco de dados / dados dos pedidos;
  • configuração / segredos necessários para a recuperação;
  • plugin/tema/código personalizado;
  • configurações de integração.

Recuperação com reconhecimento de transações

Se a loja recebe pedidos continuamente, a frequência dos backups define a possível perda de dados dos pedidos.

Um backup de banco de dados diário pode significar que até um dia de transações recentes está fora desse ponto de restauração.

Escolha a frequência dos backups com base no RPO aceitável, não apenas na conveniência.

Estratégia de backup para VPS

ambiente de teste

Teste alterações em PHP, WooCommerce, plugins, temas, HPOS e pagamentos no ambiente de teste antes da produção onde for prático.

Mas as cópias de ambiente de teste também consomem recursos de disco e, às vezes, DB/RAM/backup, então inclua-os no planejamento de capacidade.

Painel de controle, FASTPANEL ou pilha manual

O WooCommerce pode ser executado em um VPS Linux gerenciado manualmente ou através de um painel de controle de hospedagem.

Para seleção de painel genérico, consulte VPS com Painel de Controle.

Para o fluxo específico com FASTPANEL na VDSina, veja Hospedagem VPS com FASTPANEL.

Para uma implantação manual do Linux, consulte Como hospedar um site no VPS.

Um painel de controle simplifica tarefas rotineiras; ele não assume a confiabilidade do checkout, as atualizações de WooCommerce/plugins, os ajustes do banco de dados, os backups ou os incidentes.

A migração de uma loja em produção exige definir um ponto de corte dos dados

Uma migração do WooCommerce não é apenas "copiar arquivos e banco de dados".

Pedidos, estoque, carrinhos, clientes e ações agendadas podem mudar enquanto a loja está em funcionamento.

Para migração:

  • prepare e teste primeiro o destino;
  • controle as gravações finais;
  • faça a sincronização final do banco de dados e dos uploads;
  • evitar duas lojas de produção graváveis divergentes;
  • verificar os pontos de extremidade do pagamento/webhook;
  • preservar e-mail/DNS;
  • mantenha um plano de reversão.

Use Migração de site para VPS para planejar a virada completa.

Quando ampliar um VPS para WooCommerce

Amplie os recursos ou reveja a arquitetura quando as medições mostrarem:

  • filas de processo PHP repetidas;
  • saturação sustentada da CPU após otimização de cache/query/plugin;
  • Pressão RAM, swap ou OOM;
  • Latência do banco de dados / pressão do conjunto de trabalho do banco de dados;
  • Backlog / falhas do Action Scheduler causadas pela capacidade;
  • erros de checkout/pagamento sob carga máxima legítima;
  • crescimento do armazenamento reduzindo a margem de capacidade segura;
  • backups, importações ou varreduras competindo com as requisições dos clientes;
  • várias lojas/serviços competindo por um VPS.

Se o checkout for lento enquanto os recursos do servidor estiverem saudáveis, investigue as causas de pagamento/API/plugin/banco de dados antes de comprar um VPS maior.

FAQ

Quanta RAM o WooCommerce precisa em um VPS?

Não existe um valor universal. A própria orientação de escalabilidade do WooCommerce já usou 2 GB como configuração básica em infraestrutura própria. Já um VPS de 4 GB é um ponto de partida prático mais robusto para muitas lojas comerciais, pois processos PHP, banco de dados, cache e tarefas precisam coexistir.

2 GB de RAM é suficiente para WooCommerce?

Pode ser suficiente para uma loja muito pequena / leve ou configuração de baixo volume controlada. Valide a concorrência de checkout, latência de banco de dados, ações agendadas e pressão de memória antes de tratá-la como pronta para produção.

4 GB de RAM é suficiente para WooCommerce?

Para muitas lojas de pequenas empresas, 4 GB é um ponto de partida prático. Tráfego pesado, catálogos/DBs maiores, muitas integrações, assinaturas, importações ou picos de venda podem exigir mais.

Por que WooCommerce é mais pesado do que o WordPress normal?

Carrinho, checkout, conta, pedidos, estoque e muitas integrações são dinâmicos. Essas requisições continuam executando PHP e operações no banco de dados, mesmo quando as páginas públicas de catálogo/conteúdo estão em cache.

Posso armazenar em cache o checkout do WooCommerce?

O cache de página inteira deve excluir Carrinho, Checkout e Minha conta, pois essas páginas contêm dados específicos de cada cliente. Use outras camadas de cache para os dados e conteúdos adequados.

O WooCommerce precisa do Redis?

Não. Redis ou Memcached podem fornecer cache de objeto persistente quando a carga de trabalho se beneficia. Eles não substituem exclusões corretas de cache de página ou consultas eficientes.

O que é HPOS?

O HPOS armazena os pedidos em tabelas dedicadas e é o padrão para novas instalações desde o WooCommerce 8.2. Teste a compatibilidade das extensões e do código, além dos fluxos críticos da loja, antes da migração.

O que são ações programadas do WooCommerce?

São tarefas em segundo plano em fila gerenciadas pelo Action Scheduler para trabalho, como notificações de pedidos, processamento relacionado a pagamentos, webhooks e tarefas de extensão. As filas falhadas ou atrasadas são um sinal operacional.

VDSina inclui WooCommerce pré-instalado?

A página atual dos planos VDSina Standard não lista o WooCommerce como aplicativo dedicado e pré-instalado entre os grupos visíveis de modelos/aplicativos. Confira a tela de contratação antes de presumir a disponibilidade de qualquer modelo.

Um VPS é sempre melhor para WooCommerce do que hospedagem gerenciada?

Não. Um VPS autogerenciado é útil quando você precisa de controle/recursos e pode operar o servidor. A hospedagem WooCommerce/WordPress gerenciada pode ser mais segura quando a loja é crítica para os negócios e a administração do servidor não tem proprietário interno.
