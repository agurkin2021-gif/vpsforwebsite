マネージドVPSとアンマネージドVPSの主な違いは、**サーバー構築後の運用を誰が担当するか**です。CPU、RAM、ディスクが同じでも、OS、セキュリティ、Web環境、バックアップ、監視、障害調査、復旧の責任分担が変わります。

VPS選び全体については、[Webサイト向けVPS]({{< relref "_index.md" >}})をご覧ください。

## 構成の目安 {#quick-answer}

| 選択肢 | 適する状況 | 主なリスク |
|---|---|---|
| **アンマネージド・自己管理型VPS** | 自分やチームでLinux/Windowsを管理し、OS更新、保護、バックアップ検証、監視、障害対応を行える | 運用担当者がいなければ、安いサーバー料金以上の費用がかかる場合がある |
| **マネージドVPS** | 事業者や契約管理者に決められた管理作業を任せたい、業務停止の損失が大きい | 「マネージド」の範囲が曖昧な場合があり、対象外の作業は自分に残る |
| **アンマネージド＋有料の管理支援** | root権限や制御を保ち、インフラ費用を抑えつつ、保守や障害対応をすべて自分では行いたくない | 有料作業を依頼していない時間にも、担当者と対応手順が必要 |

選ぶ際の重要な原則は、**「マネージド」という名称ではなく、書面で示された作業内容と対応範囲を確認すること**です。

## 「マネージド」の意味は統一されていない {#managed-does-not-have-one-standard-meaning}

「マネージドVPS」は共通の技術仕様ではありません。事業者によって、この名称が示すサービス範囲は大きく異なります。

OS更新、ファイアウォール管理、監視、復元を含むプランもあれば、パネル、初期設定の支援、問い合わせ対応だけのプランもあります。WordPressプラグイン、独自コード、データベースクエリ、API、業務ロジックなど、アプリケーション側の作業は対象外の場合があります。

価格を比較する前に、次を確認します。

- 事業者が自主的に監視する対象。
- 自動または依頼に応じて適用するパッチ。
- 設定されるバックアップジョブ。
- 復元テストと実際の復元作業が含まれるか。
- 対象サービス：Nginx/Apache、PHP、データベース、メール、Redis、Dockerなど。
- アプリケーションの障害調査が含まれるか。
- 緊急対応は24時間365日か、営業時間内だけか。
- 想定応答時間とエスカレーション手順。
- どのような変更で管理サービスの対象外になるか、制限されるか。
- rootアクセスが許可されるか、独自変更後の扱いはどうなるか。

書面の対応範囲が実際に任せたい作業と一致してこそ、マネージドVPSの価値があります。

## 契約前に管理サービスの表現を確かめる {#decode-management-claims-before-paying}

販売ページの表現は、作業の担当が決まっている証拠ではありません。具体的な内容を確認する出発点として使います。

| プランページの表現 | 書面で確認する内容 |
|---|---|
| **24時間365日サポート** | サーバーを自主的に監視するか、問い合わせなしで対応する障害、ゲストOS・アプリケーション作業の有無 |
| **フルマネージド** | OS、ファイアウォール、Web環境、データベース、バックアップ、監視、障害対応の具体的な作業、対応ソフトウェア、対象外事項 |
| **バックアップ込み** | 頻度、保持期間、サーバー外の保存先、失敗監視、復元テスト、復元の担当者 |
| **監視込み** | 監視対象、しきい値、通知先、対応権限を持つ担当者、時間外対応 |
| **セキュリティ管理** | パッチ適用の頻度、ファイアウォールの担当、SSH/RDP方針、脆弱なパッケージの扱い、侵害時の対応 |
| **移行込み** | ファイル、データベース、DNS、メール、最終書き込み、切り戻し、アプリケーション固有の作業範囲 |
| **コントロールパネル込み** | パネル・ライセンスの範囲。OS更新、復旧、監視、障害対応の担当は別途確認 |

事業者が名称を具体的な担当作業に置き換えて説明できない場合、比較時には曖昧な作業を自分の担当として扱ってください。

## 責任分担表 {#responsibility-matrix}

この表を基本的な整理に使い、マネージドの列は事業者が書面で示す実際の範囲に置き換えてください。

| 作業 | アンマネージドVPS | マネージドVPS |
|---|---|---|
| 物理機器、電源、ネットワーク、ハイパーバイザー | 事業者 | 事業者 |
| VPS作成・OSイメージ | 通常は事業者が導入ツールを提供 | 事業者。初期設定支援を含む場合もある |
| OS更新とセキュリティパッチ | **利用者** | **契約に含む場合のみ**事業者 |
| ファイアウォール・SSH・RDPの保護 | **利用者** | **契約に含む場合のみ**事業者 |
| Webサーバーと実行環境の設定 | **利用者** | 対応する構成では含まれる場合がある |
| データベース管理 | **利用者** | 一部を含む場合がある。制限の確認が必要 |
| TLS証明書と更新 | **利用者、または自分の自動化・パネル** | 含まれる場合がある |
| バックアップジョブの設定 | **利用者** | 含まれる場合がある |
| 復元テスト | **利用者** | 別の担当範囲になることが多いため要確認 |
| 監視と通知 | **利用者** | 含まれる場合がある |
| 停止時の対応 | **利用者・管理者** | 管理契約の範囲内のみ事業者 |
| WordPress・プラグイン・独自コードの問題 | **利用者・開発者** | 対象外または制限付きが一般的 |
| 必要スペックと拡張の判断 | **利用者** | 共同で判断する場合が多い。要確認 |
| DNS・メール・外部連携 | **明記がなければ利用者** | 対応範囲は大きく異なる |

担当者が明示されていない作業は、確認できるまで委任済みと考えないでください。

## アンマネージドVPSで必要になる作業 {#what-unmanaged-vps-really-requires}

アンマネージドは、サポートの質が悪いという意味ではありません。事業者はインフラを提供し、別途合意がなければサーバー管理は利用者が担当します。

本番サイトでは、次の作業に担当者が必要です。

- 初期のセキュリティ強化。
- SSH/RDPアクセスとアカウントの保護。
- OS・カーネル・パッケージの更新。
- ファイアウォールと公開サービスの管理。
- Webサーバー、PHP・Node・Python、データベースの設定。
- TLSの更新。
- ログの確認。
- 必要に応じたマルウェア・不正利用への対応。
- ディスク空き容量の監視。
- CPU・RAM・データベースの監視。
- バックアップのスケジュール設定。
- 復元テスト。
- 障害の原因調査。
- 更新や設定変更に失敗した後の復旧。
- アプリケーションのデプロイ調整。

これらの担当者を挙げられない場合、そのサーバーは自己管理されているのではなく、**運用担当者のいないアンマネージド環境**です。

### 本番でアンマネージドを選ぶ前の注意点 {#red-flags-unmanaged-is-a-poor-production-fit}

次の項目が複数当てはまるなら、業務上重要なサイトをアンマネージドVPSへ置く準備はまだ整っていません。

- OS・セキュリティ更新の担当者がいない。
- バックアップを定期実行しているが、復元したことがない。
- ディスク、CPU、メモリ、データベース、稼働状況の通知を確認する人がいない。
- 営業時間外の障害に対応できる人がいない。
- サーバーを理解する開発者が1人だけで、手順書がない。
- サポート対象外のゲストOSやアプリケーションの問題も、事業者が修復してくれるとチームが考えている。
- 停止によって売上、顧客の利用、業務が止まる。

必ずマネージドを契約する必要があるという意味ではありません。自社チーム、管理サービス事業者、契約管理者のいずれかが、すべての運用作業を明確に担当できる状態にすることが必要です。

リソースの選定は、[VPSのスペックの選び方]({{< relref "vps-sizing-for-website.md" >}})をご覧ください。

## マネージドVPSで確認すべき対応範囲 {#what-managed-vps-should-cover}

管理サービスは運用作業を減らせますが、その境界を明確にする必要があります。

次の質問への回答を書面で確認してください。

- サーバーを自主的に監視するか。
- OS・セキュリティ更新を計画し、適用するか。
- ファイアウォールやセキュリティ強化の作業を含むか。
- どのWeb・データベース構成に対応するか。
- バックアップジョブを含むか。
- 誰が復元テストを行うか。
- 障害時に誰が復元するか。
- サービス障害を自動的に調査するか、問い合わせ後にだけ対応するか。
- アプリケーション側の障害調査を含むか。
- WordPressやプラグインの問題は対象か。
- データベースの性能問題は対象か。
- 独自パッケージ、Docker、サービスに対応するか。
- どの応答時間目標が適用されるか。
- 時間外の障害対応を含むか。
- 移行を含むか。
- プラン外で追加料金になる作業は何か。

「フルマネージド」「24時間365日サポート」という表現や、パネルがあることだけから判断しないでください。

## コントロールパネルと管理サービスは別 {#control-panel-is-not-management}

パネルは、次のような日常の管理作業を簡単にできます。

- ドメインと仮想ホスト。
- TLS証明書。
- PHPバージョン。
- データベース。
- ユーザー。
- メールボックス。
- ファイル管理。
- 定期実行ジョブ。

ただし、パネルが自動的に次を担うわけではありません。

- OSにパッチを当てる時期を判断する。
- バックアップからの復旧をテストする。
- ディスク容量不足の障害を調査する。
- 問題のあるデータベースクエリを直す。
- 認証情報の侵害に対応する。
- 午前3時にサイトの状態を確認する。
- 失敗したデプロイから復旧する。

パネルはツールです。管理サービスは、**担当責任と対応を引き受けるサービス**です。

パネルを使った管理については、[コントロールパネル付きVPS]({{< relref "vps-with-control-panel.md" >}})をご覧ください。

## サポートとサーバー管理は別 {#support-is-not-server-administration}

技術サポートとサーバー管理が重なるのは、事業者の書面の対応範囲に含まれる場合です。

インフラのサポートで扱われる代表的な問題は、次のとおりです。

- 仮想マシンが起動しない。
- ネットワークに到達できない。
- 基盤や事業者の管理画面の問題。
- ストレージや仮想化の問題。
- 事業者側の障害。

サーバー管理には、次のような作業が含まれます。

- ゲストOSへのパッチ適用。
- Nginx/Apacheの設定。
- PHP・データベースサービスの修復。
- SSH・ファイアウォールの保護強化。
- ログの調査。
- バックアップの復元。
- 独自ソフトウェアの障害調査。

これらはインフラサポートとは異なる責任範囲です。

当サイトで紹介するVDSinaでも、この区別が重要です。Standardページには**24時間体制の技術サポート**が掲載されていますが、公開QAでは**サーバー管理を別途注文する追加サービス**として説明しています。「24時間365日サポート」を「フルマネージドVPS」と解釈しないでください。これらのページは2026年10月13日に再確認しています。利用を決める前に、現在の管理範囲と契約条件を改めて確認してください。

## サーバー料金だけでなく運用費用の総額を比べる {#compare-total-operating-cost-not-only-server-price}

VPSの実際の費用は、サーバーの請求額だけではありません。

次のように考えます。

**運用費用の総額 = VPS + パネル・ライセンス + バックアップ + 監視 + 管理作業時間 + 有料サポート・管理作業 + 障害対応・復旧費用**

チームの業務にサーバー管理がすでに含まれているなら、アンマネージドVPSが最も安く済む場合があります。

一方、次の場合は結果的に高くつくことがあります。

- 開発者が日常のサーバー管理に時間を取られる。
- セキュリティ更新が遅れる。
- バックアップはあるが復元に失敗する。
- ディスクやデータベースの逼迫に誰も気づかない。
- 唯一の技術担当者が起きるまで障害対応が始まらない。
- 緊急で呼んだ外部管理者が、障害の最中に構成の把握から始める。

マネージドが必ず安いわけでもありません。十分な運用担当者がいて独自構成が必要な場合、範囲の狭い管理サービスを追加しても作業がほとんど減らず、費用だけが増えることがあります。

CPUやRAMだけでなく、**誰が責任を担うか**も費用に含めます。

次の表で比較できます。

| 費用・リスクの項目 | アンマネージド | マネージド・契約管理者 |
|---|---|---|
| VPSインフラ | 月額サーバー料金 | 月額サーバー料金 |
| パネル・ライセンス | 使う場合は追加 | 含まれる場合と含まれない場合がある |
| バックアップ保存先・ツール | 使う場合は追加 | 含まれるか確認 |
| 監視 | 自分のツールと作業時間 | 含まれるか確認 |
| 日常の管理 | 社内担当者の時間 | 管理サービス料金 |
| 時間外の障害 | 当番費用・対応遅延のリスク | 対応範囲と対象外を確認 |
| 復元・復旧作業 | 自分の担当 | 実行まで含むか確認 |
| アプリケーションのデバッグ | 開発者・管理者の費用 | 利用者・開発者の担当として残ることが多い |

月額請求の低さだけでなく、許容できる総費用とリスクの範囲で、必要な運用作業すべてに担当者を確保できる方式を選びます。

## セキュリティ・バックアップ・障害対応 {#security-backups-and-incident-response}

この3つを確認すると、管理体制が実際に機能するかが見えてきます。

### セキュリティ {#security}

次の担当者を確認します。

- セキュリティ更新。
- ファイアウォールの変更。
- SSH・RDPの接続方針。
- 脆弱性のあるパッケージへの対応。
- マルウェアや侵害の調査。
- 認証情報の定期的な変更。

具体的な保護の基本は、[VPSのセキュリティチェックリスト]({{< relref "vps-security-checklist.md" >}})をご覧ください。

### バックアップ {#backups}

次を個別に確認します。

- 誰がバックアップジョブを作成するか。
- コピーをどこに保存するか。
- 誰がジョブの失敗を監視するか。
- 誰が復元可能性をテストするか。
- 誰が実際に復元するか。
- どの時点のデータまで戻せるか。

「バックアップ込み」という表示だけでは、この6項目は判断できません。RPO/RTO、保持期間、外部コピー、復旧構成は、[VPSのバックアップ戦略]({{< relref "vps-backup-strategy.md" >}})をご覧ください。

### 障害対応 {#incident-response}

次を決めます。

- 何をきっかけに通知するか。
- 誰が受け取るか。
- 誰に対応権限があるか。
- 営業時間外はどう対応するか。
- 事業者のインフラと自分のゲストOS・アプリケーションの境界。
- エスカレーション手順。

移行と切り戻しの計画は、[WebサイトのVPS移行]({{< relref "website-migration-to-vps.md" >}})をご覧ください。

## rootアクセスと変更管理 {#root-access-and-change-control}

アンマネージドVPSでは、一般に大きな自由度があります。root・管理者権限、独自パッケージ、独自のファイアウォール設定、非対応サービスを使うかは自分で決めます。

マネージドVPSでもroot権限を使える場合がありますが、管理範囲には境界があります。非対応パッケージや手動変更による問題は、事業者が対応を引き受けない場合があります。

マネージドを選ぶ前に、次を確認してください。

- root・管理者権限を保持できるか。
- どの変更に対応しているか。
- 変更はサポート経由で行う必要があるか。
- 事業者が非対応の設定を元に戻すことがあるか。
- Docker、独自カーネル、外部パネルの導入で管理範囲が変わるか。
- 誰が変更内容を記録するか。

制限のない制御が不可欠なら、対応構成が狭いマネージドプランより、アンマネージドと十分な能力を持つ管理者の組み合わせが合う場合があります。

## 中間の選択肢：アンマネージド＋有料管理 {#the-middle-ground-unmanaged-plus-paid-admin}

すべて自分で行うか、フルマネージドを買うかの二択ではありません。

次の組み合わせも実用的です。

- アンマネージドVPS。
- 必要に応じたコントロールパネル。
- 自動監視。
- 独立したバックアップ。
- 文書化した復元手順。
- 有料・都度依頼の管理者。
- 障害時のエスカレーション先。

日常運用を把握しており、移行、保護強化、障害、複雑な変更で専門家の支援を受けたい場合に機能します。

誰も監視せず、長時間の停止後に初めて管理者へ連絡する体制では機能しません。併用型でも、運用責任者を明確にする必要があります。

## 処理内容と業務上のリスクで選ぶ {#choose-by-workload-and-business-risk}

### テスト・ステージング・趣味のサーバー {#test-staging-or-hobby-server}

障害の業務への影響が小さく、運用を学ぶ目的もあるなら、アンマネージドは合理的な選択肢です。

### 業務用Webサイト {#business-website}

十分な能力のある担当者がパッチ、バックアップ、監視、障害対応を担えるなら、アンマネージドでも運用できます。そうでなければ、マネージドや有料管理で運用リスクを減らせます。

### WooCommerce・会員制・取引を扱うサイト {#woocommerce-membership-or-transactional-website}

パッチ漏れ、復元失敗、長時間停止の損失は、月額料金の差をすぐに超える場合があります。チームにサーバー運用体制がなければ、通常サポートにアプリケーション運用まで期待せず、範囲の明確な管理サービスを選んでください。

### 複数の顧客サイト {#multiple-client-websites}

全サイトの障害を誰が担当し、1台の障害が複数顧客に影響するかを確認します。システム管理能力のある制作会社ならアンマネージドの制御を好む場合があります。運用担当者がいなければ、実際に機能する管理・エスカレーション体制が必要です。

### 独自アプリケーション・特殊な構成 {#custom-application--unusual-stack}

アンマネージドは自由度が高いことが多いものの、導入したものをチームで運用できることが前提です。マネージドでは、非対応の実行環境、コンテナー、独自サービスが対象外になる場合があります。

## よくある質問 {#faq}

### アンマネージドVPSと自己管理型VPSは同じですか？ {#is-unmanaged-vps-the-same-as-self-managed-vps}

通常は同じ意味です。別途サービスで定められていない限り、仮想マシン内部の管理の多くを利用者が担当します。

### アンマネージドVPSにも技術サポートはありますか？ {#does-unmanaged-vps-include-technical-support}

ある場合があります。インフラやアカウントのサポートが提供されても、OS、セキュリティ、バックアップ、Web環境、アプリケーションの管理まで自動的に含まれるわけではありません。

### コントロールパネルがあればマネージドVPSですか？ {#does-a-control-panel-make-a-vps-managed}

いいえ。パネルで多くの作業は簡単になりますが、更新、セキュリティ、バックアップ、監視、障害対応の担当者は必要です。

### マネージドVPSのほうが安全ですか？ {#is-managed-vps-more-secure}

自動的に安全になるわけではありません。能力のある管理者が実際にパッチ、保護強化、監視を行えば、運用リスクを減らせます。安全性は名称ではなく、実際の管理範囲と実行に左右されます。

### マネージドVPSは必ず高くなりますか？ {#is-managed-vps-always-more-expensive}

月額請求は通常高くなりますが、貴重な管理時間を節約したり、高額な障害を防いだりできれば、総費用が下がる場合があります。時間、ツール、バックアップ・監視費用、復旧リスクを比較してください。

### マネージドVPSでroot権限を使えますか？ {#can-i-use-root-access-on-a-managed-vps}

使える場合があります。方針は事業者ごとに異なります。root・管理者権限を保持できるか、独自変更で管理責任が制限・解除されるかを確認してください。

### アンマネージドVPSは誰に向いていますか？ {#who-should-choose-unmanaged-vps}

サーバー更新、保護強化、バックアップ、復元テスト、監視、障害対応を確実に担当でき、構成全体の制御を重視する利用者やチームです。

### マネージドVPSは誰に向いていますか？ {#who-should-choose-managed-vps}

本番サーバーを自力で保守する時間、技能、待機体制がなく、明確な範囲の運用サービスを必要とするチームです。

### 24時間365日サポートとマネージドVPSは同じですか？ {#is-247-support-the-same-as-managed-vps}

いいえ。24時間365日の技術サポートを提供しながら、サーバー管理は別サービスという場合があります。書面の対応範囲を確認してください。
